# Покрытие фильтров Sales Navigator — 2026-10-05

## Результат проверки

Фильтр по школе действительно отсутствовал: строгая схема поиска отклоняла `schools`, а браузерный сценарий не содержал School. Добавлены `filters.schools`, выбор нескольких учебных заведений, открытие расширенного списка фильтров, удаление повторов и подтверждение каждого выбранного значения. Выбор требует точного названия; похожая школа с более длинным названием не используется как замена.

Проверены схема MCP, таблица селекторов и цикл применения фильтров. Все параметры, которые схема принимала до изменения, имели реализацию. То есть остальные пробелы — отсутствующие возможности API, а не поля, которые принимались и молча игнорировались. Таблицы селекторов теперь проверяются TypeScript на полноту относительно схемы.

Сопоставление выполнено с [официальным перечнем фильтров LinkedIn](https://www.linkedin.com/help/sales-navigator/answer/a1461507) и сохранёнными HTML-снимками интерфейса от 2026-10-01. Наличие конкретного фильтра в текущем аккаунте зависит от тарифа и подключённых функций. Живая проверка 2026-10-05 остановилась на `AUTH_REQUIRED`: сохранённая сессия перенаправляет на `/sales/login`.

## Поддерживаются в коннекторе

| Параметр | Возможность |
|---|---|
| `keywords` | Ключевые слова |
| `currentTitles` | Текущая должность |
| `pastTitles` | Прошлая должность |
| `geographies` | Регион, страна или город |
| `industries` | Отрасль |
| `currentCompanies` | Текущая компания |
| `schools` | Школа/университет — добавлено в этом изменении |
| `companyHeadcounts` | Восемь диапазонов численности от 1–10 до 10001+ |
| `connectionDegrees` | Первая, вторая и третья+ степень связи |

Для школы название должно совпадать с подсказкой LinkedIn. Это фильтр по образованию в профиле, а не поиск упоминания школы среди ключевых слов. Пример: `{"filters":{"schools":["Stanford University"]},"limit":5}`.

## Ещё не реализованы

| Группа | Отсутствующие фильтры |

| Компания | Прошлая компания; тип компании; расположение штаб-квартиры |

| Личные данные | Имя; фамилия; язык профиля; общий стаж; членство в группах |
| Намерение покупателя | Интерес компании к вашему бизнесу; интерес к категории продукта; подписка на вашу компанию; недавний просмотр вашего профиля; недавний просмотр страницы вашей компании |
| Связи | Контакты выбранного человека; контакты коллег через TeamLink; бывшие клиенты; бывшие коллеги; общий опыт |
| Активность | Недавняя смена работы; недавние публикации |
| Работа со списками | Персоны; списки компаний; списки лидов; люди в CRM; история взаимодействий; сохранённые лиды и компании |

Дополнительные пробелы внутри уже поддерживаемых фильтров:

- География: почтовый индекс и радиус не поддерживаются.
- Численность компании: отдельная категория самозанятых не поддерживается. В сохранённом интерфейсе она есть наряду с восемью диапазонами.
- Связи: варианты участников общих групп, TeamLink и Executive TeamLink не принимаются схемой; доступность TeamLink нужно сверить с аккаунтом.
- Исключение значений: API поддерживает включение, но не отдельные условия исключения.

Функция, уровень должности, смена работы, публикации, участники общих групп и категория самозанятых подтверждаются сохранёнными HTML-снимками. Остальные пропуски установлены сопоставлением API с официальным перечнем; в текущем аккаунте после повторного входа их нужно проверить отдельно.

## Проверки изменения

- Валидация нескольких названий, пробелов, длины и количества; поле школы публикуется в MCP-схеме.
- Браузерные тесты без обращения к LinkedIn: отдельная школа; несколько школ и повторы; сочетание с географией; очистка; продолжение по cursor; смена школы; похожее название; исчезновение выбора; Unicode и скобки в названии.
- Все 20 автоматических тестов прошли; проверка TypeScript и сборка успешны.
- Живые сценарии для следующей проверки: `test/manual/filter-inventory-live.ts` и расширенный `test/manual/filter-regression-live.ts`. Они требуют предварительного входа через `npm run login`.

После сборки постоянный browser-worker должен загрузить новый код: остановите его командой `npm run worker:stop`, следующий вызов автоматически запустит обновлённый процесс. MCP-клиенту нужно переподключение, чтобы перечитать схему поиска.

В ходе этого изменения прежний worker уже остановлен. Следующий вызов запустит обновлённый процесс автоматически.
