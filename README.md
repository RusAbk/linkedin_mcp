# LinkedIn Sales Navigator Agent Connector

Локальный MCP-коннектор, который превращает работу с LinkedIn Sales Navigator в несколько крупных операций для ИИ-агента. Браузерные клики, ожидания, фильтры, пагинация и извлечение полей выполняет Playwright; модель получает компактный структурированный результат.

Для удалённого доступа есть отдельный [портал подключения в `web`](web/README.md): управление пользователями, отдельная сессия LinkedIn для каждого аккаунта, персональные MCP-ключи и Streamable HTTP endpoint. Пользователю достаточно войти на сайт и добавить конфигурацию в агент; сервер разворачивается через Docker рядом с другими приложениями и существующим Nginx.

## Что уже реализовано

- отдельный browser-worker, который переживает завершение MCP и CLI-команд и держит Chrome открытым;
- отдельные постоянные вкладки для поиска и профилей;
- последовательное выполнение браузерных операций для одного аккаунта;
- поиск людей по ключевым словам, текущим и прошлым должностям, географии, индустриям, текущим компаниям, школам/университетам, размеру компании и степени связи;
- извлечение карточек результатов и данных профиля;
- сообщения/InMail и приглашения в контакты;
- `commit=false` для безопасного предварительного просмотра;
- SQLite-журнал и `operationId`, защищающие от автоматической повторной отправки после сбоя;
- диагностический HTML и скриншот при несовпадении интерфейса с селекторами;
- MCP через `stdio`.

Коннектор не обходит CAPTCHA, проверки аккаунта или ограничения LinkedIn. При такой проверке он возвращает `CHALLENGE_REQUIRED`, после чего её нужно пройти вручную в открытом браузере. Автоматизированный доступ и отправка действий могут нарушать условия LinkedIn и привести к ограничению аккаунта; по умолчанию отправляющие команды работают только как preview.

## Установка и первый вход

Требуются Node.js 24+ и Google Chrome.

```powershell
npm install
Copy-Item .env.example .env
npm run build
npm run login
```

Команда `login` автоматически запустит browser-worker и откроет окно Chrome. Войдите в LinkedIn, откройте Sales Navigator и после завершения возможных проверок нажмите Enter в терминале. Сессия сохраняется в `.data/browser-profile`; этот каталог и база операций исключены из Git. После завершения команды Chrome остаётся открытым для следующих вызовов.

Проверить сессию:

```powershell
npm run doctor
```

Проверить постоянный worker или явно остановить его:

```powershell
npm run worker:status
npm run worker:stop
```

Обычно запускать worker отдельно не требуется: MCP и CLI подключатся к существующему процессу или запустят его автоматически. Для ручного запуска собранной версии используется `npm run worker`.

Поиск требует хотя бы один критерий. Например, быстрый поиск по ключевым словам:

```powershell
npm run search -- '{"filters":{"keywords":"B2B SaaS"},"limit":5}'
```

Вызов без критериев возвращает `INVALID_INPUT`, поскольку текущий интерфейс Sales Navigator показывает только приглашение применить фильтры и не формирует выдачу.

При изменении интерфейса выполните команду ниже. По умолчанию она откроет поиск людей перед созданием снимка:

```powershell
npm run inspect
```

Для другой страницы передайте полный URL LinkedIn вторым аргументом.

Снимок и HTML появятся в `.data/diagnostics`. Основные селекторы находятся в `src/linkedin/selectors.ts`, сценарии — в `src/linkedin/sales-navigator-adapter.ts`.

## Подключение к MCP-клиенту

После `npm run build` добавьте сервер в конфигурацию MCP-клиента. Для текущего расположения проекта:

```json
{
  "mcpServers": {
    "linkedin-sales-navigator": {
      "command": "node",
      "args": [
        "--env-file-if-exists=C:\\Users\\swiss\\OneDrive\\Desktop\\Linkedin\\.env",
        "C:\\Users\\swiss\\OneDrive\\Desktop\\Linkedin\\dist\\src\\mcp-server.js"
      ],
      "env": {
        "LINKEDIN_ACTION_MODE": "review"
      }
    }
  }
}
```

Рабочий каталог MCP-клиента не имеет значения: пути к данным вычисляются относительно проекта. Несколько перезапусков MCP подключаются к одному worker на `127.0.0.1:17381`, поэтому Chrome и авторизованная сессия не перезапускаются. Доступ к локальному worker защищён случайным токеном из `.data/browser-worker.token`.

## MCP-инструменты

| Инструмент | Назначение |
|---|---|
| `linkedin_worker_status` | Показывает PID, время работы и прогретые вкладки worker |
| `linkedin_session_status` | Проверяет вход, доступ к Sales Navigator и режим действий |
| `linkedin_search_people` | Применяет фильтры, собирает карточки и возвращает `nextCursor` |
| `linkedin_get_profile` | Читает доступные поля профиля и раздел опыта |
| `linkedin_get_profiles` | Пакетно читает до 25 профилей за один вызов агента |
| `linkedin_send_message` | Предпросмотр или отправка сообщения/InMail |
| `linkedin_send_connection` | Предпросмотр или отправка приглашения с заметкой |
| `linkedin_get_operation` | Читает сохранённый результат отправляющей операции |

Пример поиска:

```json
{
  "filters": {
    "keywords": "B2B SaaS",
    "currentTitles": ["Founder", "CEO"],
    "geographies": ["Vietnam"],
    "companyHeadcounts": ["11-50", "51-200"],
    "connectionDegrees": ["2nd"]
  },
  "limit": 25
}
```

`nextCursor` имеет вид `page:2` или `page:1:offset:5`, если лимит остановил сбор внутри страницы. Передайте его с теми же фильтрами, чтобы продолжить поиск без пропуска оставшихся карточек. Пока worker жив, коннектор продолжает с уже открытой страницы и не применяет те же фильтры повторно. После перезапуска worker он восстановит позицию с начала поиска; содержимое выдачи LinkedIn между вызовами может измениться.

Фильтр `schools` ищет по учебному заведению в образовании профиля, например:

```json
{
  "filters": {
    "schools": ["Stanford University", "Harvard University"],
    "geographies": ["United States"]
  },
  "limit": 25
}
```

Передавайте точные названия из подсказок School. В одном фильтре значения объединяются через «ИЛИ», разные фильтры — через «И». Повторы удаляются. До 20 названий, каждое до 200 символов. Несуществующая школа возвращает `FILTER_UNAVAILABLE`; похожее более длинное название не подставляется автоматически.

Полный аудит покрытия: [FILTER-AUDIT.ru.md](FILTER-AUDIT.ru.md). Добавление `schools` проверено автоматическими браузерными тестами; живая проверка в аккаунте на 2026-10-05 требует повторного входа в LinkedIn. После обновления сборки перезапустите MCP-клиент для обновления схемы инструментов. Постоянный browser-worker также нужно перезапустить, чтобы он загрузил новый код (`npm run worker:stop`; следующий вызов запустит его автоматически).

## Отправляющие операции

По умолчанию `.env.example` содержит:

```text
LINKEDIN_ACTION_MODE=review
```

В этом режиме следующий вызов возвращает только план:

```json
{
  "operationId": "campaign-42-person-17-message-1",
  "profileUrl": "https://www.linkedin.com/in/example/",
  "text": "Hello ...",
  "commit": false
}
```

Для реальной отправки установите `LINKEDIN_ACTION_MODE=execute`, перезапустите MCP-сервер и вызовите инструмент с `commit=true`. Для одного логического действия всегда используйте один и тот же `operationId`. Повторный вызов с тем же ID и теми же параметрами возвращает сохранённый результат; тот же ID с другим текстом или получателем возвращает `ACTION_CONFLICT`.

Если клик был сделан, но подтверждение результата не появилось, операция получает состояние `unknown`. Коннектор сначала пытается найти уже отправленное сообщение или состояние `Pending` и не повторяет потенциально выполненное действие вслепую.

## Разработка

Ручные и интеграционные проверки соответствия реальному интерфейсу: [90 тест-кейсов](TEST-CASES.ru.md) и [шаблон отчёта](test/manual/RUN-TEMPLATE.ru.md). Набор включает поиск, профили, preview, отправки, повторные вызовы и диагностику; ожидаемые результаты необходимо сверять с состоянием браузера.

```powershell
npm run check
npm test
npm run build
```

Структура проекта:

- `src/mcp-server.ts` — MCP-контракты;
- `src/browser-worker.ts` — постоянный локальный процесс и его RPC-интерфейс;
- `src/worker/worker-client.ts` — автозапуск worker и подключение клиентов;
- `src/connector-service.ts` — preview, режим отправки и идемпотентность;
- `src/linkedin/sales-navigator-adapter.ts` — сценарии интерфейса;
- `src/browser/browser-manager.ts` — постоянная сессия Chrome и очередь;
- `src/storage/operation-store.ts` — SQLite-журнал операций.

Первая живая проверка должна выполняться на одном языке интерфейса и одном тестовом аккаунте. LinkedIn регулярно меняет DOM и проводит A/B-тесты, поэтому после первого `npm run login` нужно прогнать поиск с 1–2 фильтрами и при необходимости скорректировать централизованные селекторы по диагностическому снимку.
